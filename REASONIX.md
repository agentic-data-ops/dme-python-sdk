# REASONIX.md — dme-python-sdk

Python package (`pydme`) for Huawei DME storage O&M — modular CLI + SDK over the DME REST API.

## Stack
- **Language:** Python 3 (setuptools build)
- **Key dep:** `requests>=2.28`
- **CLI framework:** stdlib `argparse`
- **API client pattern:** auto-login session via `DMEAPIClient`

## Layout
- `pydme/client.py` — REST client: `DMEAPIClient` (central auth+CRUD), `StorageAPIClient` (device-native proxy), `BaseClient`
- `pydme/cli.py` — `DMECLI` controller; entry point for `pydme` command; mock-only topics (`MOCK_ONLY_TOPICS`, currently `memstore`) skip DME parameter validation and login via `_requires_dme_login()`
- `pydme/mockdata.py` — local mock store for topics without a real API (`~/.config/pydme/mock/memstore.json`), seeded with sample data on first access
- `pydme/actions/` — 18 topic modules (protect/san/nas/storage/system/hci/memstore/…), 487 action functions total; the action registry comes from `pydme/config/i18n/actions_<lang>.yaml` (no `ACTIONS` dict in code)
- `pydme/config/i18n/` — `actions_<lang>.yaml` (topic tree: name/description/actions/subtopics + func/params) and `funcs_<lang>.yaml` (`<topic>.<func>` → full docstring); generated by `.reasonix/scripts/gen_actions_i18n.py`
- `pydme/config/blacklist.json` — 144 destructive/risky action keys (incl. `virt` 21, `memstore` 3), bypassed via `--accept-risk` or `DME_ACCEPT_RISK`
- `.reasonix/plans/` — plan documents (completed, 0 pending)
- `.reasonix/scripts/` — test runner shell scripts (`00-lib.sh` with `exec_test` function), helper scripts (`check_prose.py`)
- `.reasonix/reference/` — structured API reference doc (1.7MB, 517+ APIs)

## Commands
- **Dev install:** `pip install -e .` (or `install.sh`: git pull → pip uninstall → reinstall)
- **CLI entry:** `pydme --list-topics` or `python -m pydme.cli`
- **CLI pattern:** `pydme <topic> <subtopic> <action> [--param value …]`
- **Config env vars:** `DME_API_ENDPOINT`, `DME_API_USERNAME`, `DME_API_PASSWORD`, optional `DME_API_AUTH_TOKEN`
- **No test runner/linter** in pyproject.toml — testing uses `.reasonix/scripts/` shell scripts
- **End-to-end test status:** 420/427 covered (98.4%), 17 env-limited, 2 SKIP (A800 only), 0 pending; 49 new actions (hci×5, virt×44) statically verified via `--help` (see `.reasonix/output/106-verify.md`), no E2E env yet; **memstore 11 actions are mock-backed**, verified end-to-end with an isolated HOME (see `.reasonix/output/600-verify.md`)

## Conventions
- **Action functions** take `client: DMEAPIClient` as first arg; optional params default to `None`
- **Action registry** lives in `pydme/config/i18n/actions_<lang>.yaml` (per action: `name` short key, `func`, `params`, `subtopic`); `cli.py` builds it via `pydme.i18n.load_actions_registry()` and resolves `func` to the module callable
- **Docstrings** live in `pydme/config/i18n/funcs_<lang>.yaml` (key `<topic>.<func>`), Chinese in `funcs_zh_CN.yaml`, English in `funcs_en_US.yaml`; structured `Args:` with `param: desc (constraints)。可选值：enum (desc), …`; `Returns:` starts with `{` JSON-style. Parser relies on `参数格式如下：[{` / `属性格式如下：{` as entry markers — using bare `格式：{` causes internal fields to leak as CLI params in `--help`. All field lines end with `,`.
- **Generated files** go in `.reasonix/`: plans → `plans/`, scripts → `scripts/`, output → `output/`
- **Blacklist** loads user override `~/.config/pydme/blacklist.json` if present; falls back to package default

## Watch out for
- **Docstring format is parsed by `cli.py`** — the parser tokenizes `参数格式如下：[{` / `属性格式如下：{` markers. Deviating (e.g. `格式：{`) breaks CLI help rendering. The Returns section must start with `{` on the line after `Returns:` with no prefix text.
- **Topics are read from `pydme/config/i18n/actions_<lang>.yaml`** — adding a topic/action requires regenerating (or editing) the YAML; the `func` must exist in the corresponding `pydme/actions/<topic>.py` module. No registration in `cli.py`.
- **No pytest/unittest in the repo** — only `.reasonix/scripts/` shell-based integration tests.
- **Blacklist two-source:** package default (`pydme/config/blacklist.json`) and user override (`~/.config/pydme/`). The user version is authoritative.
- **NFS share_path 格式**：需为 `/{filesystem_name}/{dtree_name}` 两层路径，且 DTree 须先存在。
- **CIFS create 的 fs_id**：`fs_id` 是顶层参数，不在 `create_cifs_param` 内部。
- **cifs_share_show_permissions**：URL 含 `{cifs_share_id}` 占位符，调用 `client.post()` 时必须传入 `params={"cifs_share_id": cifs_share_id}`。
- **Kube API**：字段名为 `namespace_name` 而非 `namespace`（在 pod_list / pvc_list 中）。
- **GFS migration_task_operate**：`operate_type` 为 `str` 类型，取值 `"start"` 或 `"stop"`。
- **hci topic 为 direct-action**：`hci` 无 subtopic，命令层级为 2 级（`pydme hci list`）；YAML 中 direct actions 用 10 空格缩进（8 空格会被解析为 subtopic，导致注册表丢失）。
- **virt 嵌套 body 参数**：`vm_create`/`vm_import`/`vm_modify`/`vdisk_create_attach`/`vm_migrate*` 等含嵌套对象（`os_options`/`vm_config`/`res_config`/`disks`/`nics` 等），用 `dict`/`list` 参数承载，docstring 内用 `属性格式如下：{` / `参数格式如下：[{` 描述内部字段；`vm_config` 在 API 参考中无展开定义，docstring 注明见 DME 文档。
- **`vm_snapshot_recover` / `vm_snapshot_delete` / `vm_snapshot_show`**：URL 路径参数用 `{vm_id}`（非 `{id}`）；`vm_snapshot_delete` 的 `speed` 与 `vm_snapshot_show` 的 `is_refresh` 是 query 参数（经 `params=` 传入），`vm_snapshot_recover` 的 `snapshot_id` 在 body。
- **`vm_import` 参数名与 URL 变量冲突**：函数签名含 `url` 参数，模块内 URL 变量命名为 `url_path` 避免遮蔽。
- **`vm_nic_add` / `vm_snapshot_create` 的 `type` 参数**：函数签名用 `type`（遮蔽内置名），模块内无需内置 `type()` 时无碍。
- **memstore 为 mock-only topic**：动作读写 `~/.config/pydme/mock/memstore.json`（首次访问自动写入示例数据）；`cli._requires_dme_login()` 对 `MOCK_ONLY_TOPICS`（当前仅 `memstore`）跳过 DME 参数校验与登录（`cli.client = None`），其他 topic 行为不变；新增 mock topic 时必须同时把 topic 名加入 `cli.MOCK_ONLY_TOPICS`。
- **memstore 双向引用**：`pool.disks[].disk` ↔ `disk.pools[].pool` 必须同步维护（pool 创建/删除时两侧一起改），否则 `allocated_capacity` 失真；`disk.allocated_capacity` / `pool.capacity` / `pool.used_capacity` / `memstore.raw_capacity` / `memstore.pool_capacity` / `memstore.pool_used_capacity` 均为派生值（读取时计算，不落盘）。
- **memstore 约束**：每个记忆存储的 FRAME 独立编号（`FRAME<0~47>.SLOT<0~11>`，每 FRAME 12 盘，跨 memstore 可重复、单存储内唯一）；`disk_size` ∈ {16384, 32768, 65536}；`eviction` 1~99、`retention` >1、namespace `capacity` 1~池剩余容量；`pool create` 必须指定 `storage_id`，自动选分配容量最低的盘并按池容量均分（超出所选盘剩余容量时报错）；删除语义：memstore 有 pool / pool 有 namespace 时拒绝删除（需先清理子资源）。
- **memstore 模块内置名遮蔽**：`def list(...)` 遮蔽内置 `list`，模块内 `isinstance(x, list)` 必须改用 `builtins.list`（600 计划已踩坑，`TypeError: isinstance() arg 2 must be a type`）。
